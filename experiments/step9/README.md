# Step 9 experiments

Every number in the Step 9 documents is traceable to a file under `experiments/runs/`.
Headline numbers are generated by `experiments/step9/build_report.py`, not typed.

All data is procedurally generated. Nothing here is anatomy, is medically validated, or
supports any clinical claim.

## Modules

| Module | Purpose |
| --- | --- |
| `placement_floor.py` | the placement-blind floor, fitted on training and scored under the evaluation's own masking |
| `frame_report.py` | the frame decomposition: translation, scale, rotation, Step 8 composite, corrected metric |
| `run_baseline.py` | the Step 8 checkpoints re-scored against the floor, no retraining |
| `run_variants.py` | the variant grid: scene context and objective alignment |
| `build_report.py` | every table in the report, rendered from the run JSON |

## Reproducing

```bash
# 1. The placement-blind floor. Recompute it for any new corpus; it does not transfer.
python -m experiments.step9.placement_floor \
    --corpus datasets/processed/step8_continuous \
    --out experiments/runs/step9-placement-floor.json

# 2. Baseline: the Step 8 models against the floor. No retraining.
python -m experiments.step9.run_baseline \
    --corpus datasets/processed/step8_continuous \
    --checkpoints experiments/runs/step8-suite/checkpoints \
    --out experiments/runs/step9-baseline

# 3. Exploratory: four cells, one seed. Labelled exploratory in its own report.
python -m experiments.step9.run_variants \
    --corpus datasets/processed/step8_continuous --arm A3Lite --seeds 0 --steps 1200 \
    --out experiments/runs/step9-variants-exploratory

# 4. Confirmatory: three cells, three seeds.
python -m experiments.step9.run_variants \
    --corpus datasets/processed/step8_continuous --arm A3Lite \
    --variants S0_control S1_scene_context S2_euclidean \
    --seeds 0 1 2 --steps 1200 \
    --out experiments/runs/step9-confirmatory

# 5. Every table in the report
python -m experiments.step9.build_report
```

## Artefacts

| Path | Contents |
| --- | --- |
| `step9-placement-floor.json` | the floor, the weaker blind predictor and the oracle, per split |
| `step9-baseline/baseline_report.json` | every Step 8 checkpoint on every split, both placement conditions |
| `step9-variants-exploratory/` | the four-cell grid at one seed, with `status: exploratory` |
| `step9-confirmatory/` | three cells at three seeds, with `status: confirmatory` |
| `*/checkpoints/*.manifest.json` | per run: config including both Step 9 switches, dataset, parameters, training history |

Run identifiers say what a run varies without opening its manifest:
`s9-A3Lite-ctx-euclidean-seed2` is A3Lite with scene context, the Euclidean objective, seed 2.

## Reading the numbers

Three rules, each enforced in code rather than remembered.

**A translation error is read against the placement-blind floor, not against zero.** The
floor is what a lookup table keyed on entity identity achieves: 0.1605 to 0.1750 depending on
the split. Below it means the model has learned nothing about placement that identity alone
did not supply.

**The floor must share the evaluation's masking.** It is computed by driving the evaluation's
own loader. Computed over all twenty entities instead of the visible set it reads 0.1401,
which is 0.02 optimistic, larger than every effect Step 9 measures. A test pins the
difference.

**The rotation term carries nothing.** The frame target's rotation is a constant identity, so
`rotation_error` is structurally zero and the Step 8 composite equals the corrected placement
metric exactly. Both are reported; the agreement is the demonstration.

## Status of each suite

`status: exploratory` means one seed and no conclusion. `status: confirmatory` means three
seeds. The exploratory suite found an effect that three seeds dissolved, which is why the
distinction is recorded in the artefacts rather than left to the reader.
