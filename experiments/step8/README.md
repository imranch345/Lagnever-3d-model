# Step 8 experiments

Every result in the Step 8 documents is traceable to a file in `experiments/runs/`.
Headline numbers are generated by `experiments/step8/report_tables.py` from those files,
not typed by hand.

All data is procedurally generated. Nothing here is anatomy, is medically validated, or
supports any clinical claim.

## What each module does

| Module | Purpose |
| --- | --- |
| `relation_floor.py` | the relation-blind floor and oracle for this corpus, from the corpus alone |
| `frame_metrics.py` | position, scale, rotation and composite frame error, and the group breakdown |
| `evaluation.py` | one split under one named placement condition, over the whole split |
| `run_suite.py` | the principal comparison: five arms, three seeds, four held-out splits |
| `run_ablations.py` | R5 to R11, isolating what causes what |
| `run_entity_axis.py` | the A3Lite / A4 / A0 ladder under predicted placement |
| `editing_regression.py` | the persistent-edit regression, as a machine-readable artefact |
| `summarise_runs.py` | interim results from per-run manifests, before a suite finishes |
| `report_tables.py` | every table in the report, rendered from the run JSON |

## Reproducing

```bash
# 1. Corpus: continuous arrangements with four held-out generalisation splits
python -m datasets.whole_organ.step8_cli \
    --out datasets/processed/step8_continuous \
    --train-scenes 1200 --validation-scenes 150 --test-scenes 150 --families 40

# 2. The relation-blind floor. Recompute it for any new corpus; it does not transfer.
python -m experiments.step8.relation_floor \
    --corpus datasets/processed/step8_continuous \
    --out experiments/runs/step8-relation-floor.json

# 3. The principal suite. Every headline number comes from here.
python -m experiments.step8.run_suite \
    --corpus datasets/processed/step8_continuous --steps 1200 \
    --seeds 0 1 2 --arms A1 A1M A3Lite A3L A3 \
    --out experiments/runs/step8-suite

# 4. Ablations R5 to R11
python -m experiments.step8.run_ablations \
    --corpus datasets/processed/step8_continuous \
    --checkpoints experiments/runs/step8-suite/checkpoints \
    --arms A3Lite A3L A3 A1M A1 --seed 0 --split test_seen \
    --out experiments/runs/step8-ablations

# 5. The entity-axis ladder
python -m experiments.step8.run_entity_axis \
    --corpus datasets/processed/step8_continuous --steps 1200 --seeds 0 \
    --arms A3Lite A4 A0 --out experiments/runs/step8-entity-axis

# 6. The persistent-edit regression
python -m experiments.step8.editing_regression \
    --out experiments/runs/step8-editing-regression.json

# 7. Every table in the report
python -m experiments.step8.report_tables
```

## Artefacts

| Path | Contents |
| --- | --- |
| `step8-suite/step8_report.json` | every run, every split, both placement conditions, aggregates |
| `step8-suite/checkpoints/*.manifest.json` | one per run: config, dataset, parameters, training history, results |
| `step8-suite/checkpoints/*.pt` | weights, so the ablations act on the trained models |
| `step8-relation-floor.json` | oracle, both blind predictors, floor and headroom per split |
| `step8-ablations/ablation_report.json` | R5 to R11 with changes from the control |
| `step8-entity-axis/entity_axis_report.json` | the ladder, both conditions, every split |
| `step8-editing-regression.json` | six editing checks, pass or fail |
| `step8-corpus.log` | corpus generation, including the region audit per split |

Each run manifest records the seed, the full configuration including the teacher-forcing
schedule and its final value, the corpus identifier, the parameter breakdown, the training
history with the teacher-forcing ratio at every logged step, and the environment.

## Reading the numbers

Three rules, each learned the hard way in Step 7.

**Name the placement condition.** A relational number measured with ground-truth frames
supplied says nothing about relational reasoning, because the frames carry the arrangement.
Every table here names its condition; the headline condition is inferred.

**Read relation accuracy against the floor, not against zero.** A model with no relational
information scores 0.7874 to 0.8284 depending on the split, because many relations survive
every arrangement. Below the floor means no relational competence on that metric.

**Read level-of-detail IoU against the trivial predictor.** A finer level exposes more
entities, so its target covers more of the space: 14% of sampled points at level 1 against
55% at level 3. A model that calls everything occupied scores a raw detail gain of about
+0.41 while adding nothing. Use `lod_detail_gain_over_trivial`.
